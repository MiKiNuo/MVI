# 完整 MVI 递归组合，业务通信统一经过 Mediator

2026-09-08 已接受。面向 HIS 等复杂 UI 及同类界面多开，组合的复用单元是完整、可独立运行的 Feature；每个实例独占自己的 Store、State、ViewModel 和 EffectDispatcher。组合 Feature 自身也是完整 MVI，管理整体流程与子实例，不直接调用子 Reducer 或读取子 Store。

父子和兄弟之间的业务操作、查询及通知全部通过 Mediator。请求响应明确单个目标；通知表达已发生事实，只投递给指定组合范围内显式订阅的成员。实例身份与业务对象身份分离，通知不隐式向父级、后代或其他工作区传播。宿主负责契约接线，子 Feature 不依赖父级和兄弟的具体实现。业务决定留在 Reducer，Mediator 只负责路由与投递。

本决策取代 ADR 0004 中 Feature 对象图固定单例及同集群 StoreReference 直连的目标设计；旧运行时迁移前仍有原行为，不代表已经实施。ADR 0006 的装配确定性要求继续有效。普通子 Reducer 拆分仅是某个 Feature 的内部代码组织，不是跨 Feature 组合。

代价是独立 Store 间不具备原子状态提交，整体保存与失败恢复需明确业务流程或后台事务。资源创建、挂载与释放由宿主所有者管理，不视为绕过中介者的业务通信。
