# v2 组合通过中介者定向通信，不实现观察者订阅机制

2026-10-01 已接受，依据用户对组合模式的最新修订。不同 View 与子 View 的业务通信统一由 Mediator 定向路由到对应 Feature 实例或契约端口；v2 不提供跨 View/Feature 的 Subscribe、Publish、通知主题、订阅者列表或状态观察图。发送者不直接依赖其他 View/Feature 的实现，宿主明确目标接线，多目标业务由组合协调者明确分派。

SendAsync 等待目标处理结果，定向 Post 仅报告目标实例收件箱是否接纳；队列、验证、取消与完成语义复用统一实例入口，不为订阅者建立独立队列。View 展示自己所属 Feature 状态仍使用平台本地绑定与变化通知，框架不另建逐字段 R3 订阅，也不向业务暴露 State.Subscribe API。

本决策替代 ADR 0019 的通知订阅部分和 ADR 0021 的发布订阅接纳模型；请求目标确定性、关闭确认及其他已接受规则继续有效。此选择减少组合接线与生命周期负担，避免子 View 增多时产生观察者订阅网络。
