# 下一版本统一运行内核，默认按 State、Feature、View 编写业务

2026-10-01 已接受，适用于下一版本设计。纯状态转换与异步业务方法共用同一套运行内核及状态提交规则；每个 Feature 实例仍独立持有自己的状态、操作和生命周期。普通业务默认只编写 State、Feature 与 View，纯转换与异步流程可放在同一 Feature 中，无须逐一声明 Intent、Effect、Dispatcher、ViewModel 和生成容器。

这一选择减少重复业务声明，同时避免两种表达拥有不同的执行与错误语义；接受由框架承担更多生成、适配和诊断工作。状态模型与操作并发方向已在 ADR 0013 接受，具体 API、取消和完成契约继续在 [设计讨论](../mvi-next-design.md) 中确定。
