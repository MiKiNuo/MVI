# MVI v2 实施规格：独立 Feature、无订阅中介者通信与简洁编程模型

日期：2026-10-01。状态：用户已批准 22 项任务的粒度、依赖与验收条件，并选择本地任务跟踪。正式任务及当前可开始项见 [本地任务看板](TICKETS.md)。本规格是 v2 的验收基线；当前默认源码已实现 v2，切片 20 移除已无调用者的 v1 默认协议。功能与包验收证据见各票据；四类成本与性能预算仍由切片 21、22 提供。

## Problem Statement

使用现有 MVI 框架开发业务时，开发者需要理解并装配较多角色类型、绑定代码、生命周期对象和生成器规则。简单功能的声明成本较高，大型页面拆成多个子功能后，创建、通信、关闭和资源释放进一步增加使用负担。当前按整洁架构层次发布多个 NuGet 包，也使依赖选择与版本管理复杂。

新版本需要同时服务复杂桌面业务界面与游戏、实时交互界面。一个大型页面中的每个子功能都应是可独立运行、可复用、可多开的完整 Feature；不同 View 和子 View 通过中介者定向通信。子功能增多时，使用者不应承担越来越多的订阅、反订阅和跨实例状态观察关系。

简洁的使用方式必须保持清楚的 MVI 状态边界。开发者应能解释一次输入如何改变状态、异步结果如何回流、旧操作为什么不能覆盖新结果，以及关闭后的资源何时真正释放。吞吐、分配、界面响应和编译成本均需要测量证明。

## Solution

提供一套统一的 MVI 运行内核，让普通功能默认只编写 State、Feature、View。框架根据明确声明生成输入入口、操作调用、平台绑定和创建适配；纯状态转换与可等待 IO 的业务操作使用相同的验证、提交、取消和结果协议。

每个 Feature 实例独立拥有业务状态、操作身份和生命周期。所有输入与副作用反馈进入该实例的 Intent 入口，由 Model 计算新快照和 Effect 描述，提交后再执行外部操作，View 根据已提交快照展示。组合通过宿主管理的实例地址和契约端口完成定向中介者通信。

发布一个平台无关核心包，以及 Avalonia、Godot 两个平台入口包。单平台应用显式安装对应入口包即可获得核心运行时和所需编译资产。使用者可以直接构造 Feature，也可以接入标准依赖注入；不需要学习框架专用服务容器。

## User Stories

### 入门与包消费

1. 作为业务开发者，我希望普通功能只需要 State、Feature、View 三部分，以便减少功能开始阶段的装配工作。
2. 作为 Avalonia 开发者，我希望显式安装一个平台入口包即可使用核心与生成能力，以便避免逐层选择多个基础包。
3. 作为 Godot 开发者，我希望使用独立的平台入口包，以便获得节点与 UI 调度适配而不引入其他 UI 平台。
4. 作为无界面宿主或测试作者，我希望核心包能独立运行，以便复用业务功能而不启动 GUI。
5. 作为同时消费两个平台包的开发者，我希望核心和编译资产正确去重，以便避免重复生成、类型冲突与额外依赖。

### 输入与 MVI 状态

6. 作为业务开发者，我希望可编辑字段只声明一次，以便获得基本回写与绑定能力。
7. 作为业务开发者，我希望只为需要附加规则的输入编写纯转换，以便避免逐字段编写重复赋值代码。
8. 作为表单使用者，我希望编辑时允许业务模型可表达的中间值，以便完成输入后再触发提交验证。
9. 作为业务开发者，我希望 UI、程序调用和中介者请求遵守同一启动验证，以便按钮禁用之外的调用也不会绕过规则。
10. 作为框架使用者，我希望业务数据、加载状态和验证反馈来自一致快照，以便界面不会显示互相矛盾的状态。

### 异步操作与结果

11. 作为业务开发者，我希望在 Feature 中直观地编写异步业务流程，以便调用应用已有的异步服务。
12. 作为业务开发者，我希望外部结果通过受控状态转换回流，以便异步代码不能任意覆盖实例状态。
13. 作为调用者，我希望正常等待完成表示业务方法结束且已接纳的状态变化已提交，以便可靠地继续下一步业务。
14. 作为调用者，我希望区分执行完成、业务失败、拒绝、取消、被取代和故障，以便做出正确的后续处理。
15. 作为界面使用者，我希望慢 IO 期间其他合法输入仍可处理，并能看到对应操作的加载与错误表现，以便知道应用仍然可用。

### 并发与迟到反馈

16. 作为业务开发者，我希望同一操作默认拒绝重复启动，以便普通提交不会因重复点击而重复执行。
17. 作为搜索功能开发者，我希望 Latest 保证旧结果、旧进度和旧完成反馈不能覆盖新操作，以便服务忽略取消时结果仍然正确。
18. 作为需要顺序处理的开发者，我希望显式使用有界排队，以便保持处理顺序并在容量不足时得到明确结果。
19. 作为需要并发处理的开发者，我希望显式声明有界并行，以便控制同时执行的工作量。
20. 作为业务开发者，我希望异步结果基于提交时的当前状态应用，以便等待期间的新输入不会被开始时的旧快照覆盖。

### 独立实例与动态组合

21. 作为组件作者，我希望同一个 Feature 能在独立宿主和组合页面中运行，以便复用同一业务实现。
22. 作为工作区开发者，我希望同类型 Feature 可以同时创建多个实例，以便支持多开编辑器与多个业务对象。
23. 作为工作区开发者，我希望同一业务对象也能在两个独立实例中打开，以便实例身份与业务对象身份不被混为一体。
24. 作为组合功能开发者，我希望运行时可以添加、移除和嵌套子实例，以便支持动态工作区。
25. 作为子功能作者，我希望依赖业务契约而不是父级或兄弟实现类型，以便子功能可以独立测试和复用。

### 中介者定向通信

26. 作为组合功能开发者，我希望不同 View 和子 View 经 Mediator 定向通信，以便不建立跨实例观察者订阅网络。
27. 作为调用者，我希望需要业务结果时等待 SendAsync 完成，以便确认目标处理和有关状态提交已结束。
28. 作为调用者，我希望只需交付消息时取得 Post 或 TryPost 的接纳结果，以便明确区分接纳与业务完成。
29. 作为宿主开发者，我希望唯一目标自动绑定、多目标必须明确选择，以便路由结果不依赖类型名排序或发现顺序。
30. 作为业务协调者，我希望明确向多个目标分派消息，以便组合流程和跨范围通信具有可见的业务规则。

### View 挂载与关闭确认

31. 作为界面开发者，我希望 View 卸载后保留仍被拥有的 Feature 状态，以便 Tab 切换或重挂载可以恢复当前内容。
32. 作为界面开发者，我希望重复挂载同一实例不会重复创建连接，旧 View 的排队回调也不能更新新 View，以便避免错误展示和泄漏。
33. 作为编辑器使用者，我希望整个组合在关闭前完成未保存内容确认，以便不会只关闭一部分子功能。
34. 作为编辑器使用者，我希望任一子实例拒绝关闭后整个组合仍然可用，以便其他操作不会被提前取消。
35. 作为组合功能开发者，我希望确认期间状态或成员变化会触发重新验证，以便旧确认不能被用于关闭已经变化的组合。

### 取消、逻辑关闭与资源释放

36. 作为调用者，我希望取消等待与目标执行停止分别表达，以便不把停止等待当作业务撤销或正常完成。
37. 作为宿主开发者，我希望逻辑关闭后立即拒绝新业务与迟到写回，并能单独等待资源释放，以便交互可以结束而资源仍安全受控。
38. 作为宿主开发者，我希望子实例独立关闭后移除活动成员和路由，同时继续跟踪未释放资源，以便父级最终清理仍然完整。
39. 作为导航功能开发者，我希望目标能够关闭请求发起者并返回响应，以便不会形成等待发起者退出的死锁。
40. 作为宿主开发者，我希望不合作 IO 或释放等待超时不会导致仍在使用的资源被强制释放，以便保持资源使用安全。

### 创建、生成器与诊断

41. 作为应用开发者，我希望直接构造和标准 IServiceProvider 创建都可用，以便适配不同宿主与测试方式。
42. 作为应用开发者，我希望每个工厂创建的实例拥有独立服务范围，外部手工传入服务仍由创建方拥有，以便避免串用状态和重复释放。
43. 作为应用开发者，我希望创建失败时清理本次创建的范围与对象，以便失败不会留下部分可用实例或资源泄漏。
44. 作为业务开发者，我希望错误声明和生成失败能定位到原始业务声明，以便无需调试大量生成代码。
45. 作为库消费者，我希望默认诊断关注框架误用，以便团队不被迫采用框架仓库内部的层次命名和中文文档风格。

### UI 成本与性能证明

46. 作为大型页面开发者，我希望只更新有关字段或选择器的展示，以便无关状态变化不会刷新整页。
47. 作为游戏 UI 开发者，我希望高频 HUD 更新可以合并待展示状态，同时保留业务输入和一次性行为，以便控制主线程成本。
48. 作为框架维护者，我希望分别测量交互响应、实例资源、派发分配和生成编译成本，以便不能用单一吞吐数字掩盖其他退化。
49. 作为框架维护者，我希望在等价语义下比较最小手写实现、归档 v1、v2 和标准 DI，以便性能结论可以复现。
50. 作为框架使用者，我希望子 View 增多时不增加跨 Feature 观察者订阅或框架逐字段 R3 订阅，以便组合规模增长仍然可控。

### 交付与维护

51. 作为项目维护者，我希望保留 v1 的 main 与归档标签，在新的默认分支演进 v2，以便能够恢复和比较旧版本。
52. 作为项目维护者，我希望正式、预览和本地打包遵守一致的三包边界，以便发布结果与开发验证一致。
53. 作为框架消费者，我希望独立 NuGet 消费项目能够真实编译并运行，以便项目引用测试通过不能掩盖缺失的生成资产。
54. 作为项目维护者，我希望 v2 完成后仅保留一套默认运行协议与配套示例，以便不继续维护被替代的 v1 对象图和装配模型。
55. 作为后续实现者，我希望规格、领域术语、UML 与数据流保持一致，并有可判定的停止条件，以便按行为契约完成实现和验收。

## Implementation Decisions

### 编程模型与模块边界

- **D01 — 统一内核，独立实例。** 纯状态转换与异步 Operation 使用同一套运行、验证和提交协议。实现代码可复用，每个实例的 State、操作身份、准入状态、通信端点与生命周期独立；不采用全局 Store 或全局业务队列。
- **D02 — 三部分业务代码。** 普通作者编写 State、Feature、View。输入、操作、绑定和契约通过明确声明生成适配；不要求逐个手写 Intent、Effect、Dispatcher、ViewModel 或生成容器。公开名称可以在保持契约的前提下调整。
- **D03 — 三包发布。** 平台无关能力集中在 MiKiNuo.Mvi；MiKiNuo.Mvi.Avalonia 和 MiKiNuo.Mvi.Godot 各自依赖核心。整洁架构职责可保留为内部模块，不再按层次逐包发布，也不把两个 UI 平台强制放入一个运行时包。
- **D04 — 编译资产独立。** 生成器独立编译，作为 analyzer 资产随核心发布，不成为应用运行时依赖。平台入口转递所需资产，单平台与双平台消费都验证资产完整和去重。
- **D05 — 实现职责。** 核心承载状态与操作、组合与通信、平台无关绑定契约、诊断；平台适配承载原生 View、输入、字段投影、UI 调度和挂载。只建立职责协作所必需的契约，不为每个内部类增加接口。

### MVI 闭环与状态一致性

- **D06 — 状态单一权威。** RuntimeSnapshot 同时包含不可变业务 State、操作运行状态和单调版本。不可变约束覆盖嵌套可观察数据，不能仅凭 record 或只读集合接口认定不可变。
- **D07 — 统一入口。** UI 输入、Operation 调用、目标消息和 IO 反馈映射为所属实例的 Intent。Model 中的纯 Reducer 计算下一快照、Effect 描述和决定；Store 提交后才在门外调度展示与 Effect 执行。纯规则故障保留原快照。
- **D08 — 启动原子性。** 启动验证、并发准入与 IO 输入快照采样处于同一个短原子区间。不能先验证旧状态，再将另一个未验证状态交给 IO；不能持提交门等待 IO 或执行平台回调。
- **D09 — 反馈规则。** 反馈在提交点核对实例生命周期、操作身份、generation 与结果应用规则。继续编辑不会使框架重新套用启动业务条件而错误丢弃合法完成。失效反馈拒绝写回，不宣称撤销已经发生的外部操作。
- **D10 — 验证与回写。** 可编辑字段声明一次，普通回写由框架生成，附加规则使用纯转换。编辑允许中间值，启动条件对所有调用入口生效；CanExecute 仅提供界面反馈。需要显示的拒绝原因写入快照；被拒绝的新尝试不能覆盖当前有效执行的 Busy 状态。

### Operation 执行契约

- **D11 — 输入与更新分开。** Operation 的 Snapshot 是开始时的一致输入。UpdateAsync 将纯转换标识和不可变载荷形成内部 Intent，转换基于提交时的当前 State；不能用开始快照整体替换当前状态。更新成功返回意味着提交完成或形成有效的无变化结果。
- **D12 — 明确完成。** 正常 Completed 表示业务方法结束且已接纳的有关状态变化已提交，不等待 UI 绘制。业务失败值仍可属于正常完成。结果区分 Completed、Rejected、Canceled、Superseded、Faulted；调用方取消等待另外表达为 WaitCanceled，不伪装正常业务响应。
- **D13 — 有界并发。** 同一操作默认拒绝重复启动；Latest 请求取消旧操作并使旧结果、进度和完成反馈失效。顺序 Queue 与 Parallel 必须显式选择并有界。不同操作可并行等待 IO，业务对象一致性仍由纯规则或业务服务表达。
- **D14 — 执行调度。** 业务 Operation 默认后台执行，使用 UI 能力时进入平台调度入口。框架跟踪仍可能访问实例资源的全部执行；异步业务必须等待其子工作或将其纳入跟踪，不能把无归属后台工作视为已结束。
- **D15 — 取消与错误。** 取消不回滚已提交状态或已发生的 IO。上下文失效后 UpdateAsync 不能返回正常成功并允许业务继续；后续框架消息发送也检查有效性。可预期业务失败、协作取消和故障有不同结果；故障通过结构化结果及诊断处理，默认日志不记录敏感业务载荷。

### 组合与中介者

- **D16 — 动态所有权。** 完整 Feature 支持独立宿主、嵌套和同类型多实例。实例身份区别于业务对象 ID；所有权树、DI Scope 与视觉树分别管理。宿主持有挂载和生命周期句柄，子实例依赖业务契约。
- **D17 — 无订阅定向通信。** 不同 View 和子 View 经 Mediator 将消息交给确定实例或契约端口。目标适配将消息映射 Intent；不能绕过目标运行协议直接写 State。v2 不提供跨 Feature 的 Publish、Subscribe、通知主题、订阅者列表或状态观察图，也不建立框架逐字段 R3 订阅。
- **D18 — 确定性路由。** 范围内唯一目标可自动绑定，多候选必须由宿主明确选择实例或端口。静态可确定的歧义给编译诊断；动态缺失、歧义和关闭给明确结果，不选择第一个候选。跨范围通信显式接线，多目标业务由协调者明确分派。
- **D19 — 接纳与完成。** SendAsync 等待目标处理结束及有关状态提交；Post 或 TryPost 只报告目标收件箱接纳。复用有界实例入口，不为每种消息或接收者创建独立队列。关闭或满载时明确拒绝；接纳后的验证拒绝和处理故障通过相关结果或诊断报告，不静默丢弃，也不新增订阅通道。
- **D20 — 请求执行归属。** 接纳前取消不启动；接纳后默认由目标管理执行。调用者可以取消等待，契约可显式选择传播协作取消。发起者关闭不撤销目标已发生的业务。独立实例没有跨 Feature 原子状态提交；整体一致性由业务协调和后端事务承担。

### View、关闭与释放

- **D21 — View 独立生命周期。** 卸载释放所属平台绑定与交互连接，使旧回调失效；仍被拥有的 Feature 保留状态并可重新挂载。稳定挂载不重复创建 View 或连接。平台绑定属于本地展示适配，不形成跨 Feature 观察者关系。
- **D22 — 整组关闭确认。** 先确认整个所有权范围。任一拒绝时保持组合可用，不提前取消其他 IO 或释放其他实例。确认期间状态或成员发生相关变化则重新验证；最终停止业务之前存在明确、条件仍有效的关闭提交点。
- **D23 — 逻辑关闭与资源释放分离。** 逻辑关闭后拒绝新业务和迟到写回，移除活动成员及通信绑定，View 可以卸载。CloseResult 表达关闭结果，CloseTicket.Released 独立表达资源释放完成与失败。执行真正退出前保留其可能访问的范围，已脱离活动组合的实例仍被跟踪。
- **D24 — 等待环与不合作任务。** 导航响应不等待发起者物理退出；不允许依赖某执行退出的调用链反过来等待该执行的资源释放。可判定的自等待或依赖等待给诊断或错误。释放等待超时、取消等待均不等于释放成功，也不授权强制释放仍被使用的对象。
- **D25 — 展示成本。** 平台按有关字段或选择器投影，默认合并待展示更新，并允许明确选择中间展示状态。投影在提交门外且版本单调。展示合并不能吞掉业务输入、定向消息或一次性行为；加载覆盖层或局部表现由 View 选择。

### 创建、生成与演进

- **D26 — 标准 DI 与所有权。** 支持直接构造和标准 IServiceProvider。工厂每次创建独立实例与服务范围，构造依赖在创建时解析；手工传入服务由创建方拥有。Feature 不作为同范围内递归创建和释放自己的普通 scoped 服务；创建失败清理本次拥有的资源。
- **D27 — 增量生成与诊断。** 从明确属性和类型关系发现候选，生成强类型入口、纯转换与执行适配、命令、投影、工厂和契约描述。避免全 Compilation 的无关类型扫描；诊断覆盖错误签名、歧义、成员冲突和框架边界误用，并定位原始声明。消费者默认诊断不强制仓库内部文档语言和层次命名。
- **D28 — 基于证据优化。** 高频纯转换以不增加每次消息包装、反射或 DI 查找为目标；分别统计框架额外分配与业务 State 创建。池化、额外缓存等复杂度在测量证明必要时引入，不能为追求单项数字破坏完成、取消和消息语义。
- **D29 — 版本与交付。** main 和归档标签保留 v1，codex/mvi-v2 为新默认开发分支。正式、预览和本地打包统一发布边界。v2 替代完成后清理旧对象图、生成容器、角色样板及过时测试和示例约定，保留一套默认运行协议。

## Testing Decisions

### 测试边界与原则

主要测试边界是 Feature 的公开行为：构造实例，从生成的输入、Operation 或 Mediator 契约入口调用，断言公开快照、结构化结果、外部服务调用和生命周期结果。业务依赖使用可控替身；不为测试暴露私有队列、提交门、调度步骤或生成器内部类。

跨编译与平台的能力使用必要的消费测试：编译用户声明并调用生成入口；启动真实平台宿主验证绑定与调度；从本地 NuGet 产物创建独立消费者。公共协议测试不要求一组固定内部类或逐行生成文本快照。

并发与取消测试采用可控完成信号和屏障构造先后关系，优先复用现有 TaskCompletionSource 等测试方式，不依靠任意延时碰撞竞争条件。保持可诊断的测试超时。使用现有 TUnit 工具链；涉及共享 UI 和静态宿主的验证串行执行。

### 模块与已有测试方法

| 范围 | 外部断言 | 可复用的现有测试方法 |
| --- | --- | --- |
| Feature、状态与 Operation | 输入、服务调用、快照、完成和取消结果 | 登录全流程、验证中间件、Store 与命令行为测试 |
| 动态组合、中介者与关闭 | 目标实例、请求结果、活动成员和资源释放结果 | 实例隔离、组合请求路由、可控资源释放测试 |
| 生成器与分析器 | 合法声明能编译执行；非法声明在正确位置产生诊断 | GeneratorTestHost、生成工厂隔离、符号与增量行为测试 |
| Avalonia 与 Godot | 原生输入、加载展示、线程、挂载和节点归属 | Slot 生命周期、旧 View 解绑、Godot 节点保留测试；补真实宿主验收 |
| 包与性能 | 独立消费者运行、编译资产去重、等价负载的可复现数据 | 现有基准场景烟测与构建流程；增加真实包消费者和 v2 对照 |

归档 v1 测试中的通知订阅、旧 DI 容器和旧分层包约束不属于兼容目标，已随旧实现退役。认证业务与目录边界测试迁入 v2 测试项目；复用仍符合新协议的场景、可控时序工具和断言方法。Stub 平台测试与基准烟测不能代替真实 GUI 或性能测量。

### 必须通过的行为验收

| 编号 | 操作场景 | 通过条件 |
| --- | --- | --- |
| T01 | 普通字段回写与附加输入转换 | 一次字段声明可用；额外规则仅针对有关输入；只读字段不能通过绑定写入 |
| T02 | UI、程序调用和中介者触发无效提交 | 走同一启动验证；外部服务未调用；可见拒绝原因来自已提交快照；正在运行的操作不被拒绝尝试改成空闲 |
| T03 | 验证与输入变化竞争 | 实际交给 IO 的快照就是通过启动验证的快照，不能将新输入套用旧验证结果 |
| T04 | IO 等待期间继续编辑并返回结果 | IO 不阻塞其他合法输入；结果转换基于当前 State，保留无关的新编辑；业务与操作状态保持一致版本 |
| T05 | 完成、业务失败、故障和取消 | 结果类型与载荷正确；正常等待结束后有关状态已提交；UI 绘制可稍后发生；取消不回滚先前提交 |
| T06 | 默认重复启动、Queue 和 Parallel 达到限制 | 默认重复请求被拒绝；Queue 顺序正确；并行工作量受限；容量不足有明确结果且不静默丢消息 |
| T07 | Latest A/B，A 忽略取消后迟到 | A 的结果、进度和完成反馈均不能覆盖 B 的 State 或运行状态；拒绝不冒充外部 IO 已撤销 |
| T08 | 两个同类型实例及唯一、歧义、缺失目标 | 状态、操作和路由隔离；唯一目标可用；歧义和缺失明确失败；指定目标时只影响该实例 |
| T09 | SendAsync 与 Post 接纳后延迟处理 | SendAsync 等待处理和提交；Post 可先返回接纳；后续验证失败和处理故障有相关结果或诊断；满载与关闭明确拒绝 |
| T10 | 请求等待取消、目标继续执行与显式传播取消 | 默认取消只结束调用者等待，不能伪装目标成功或停止；显式传播按契约处理；接纳前取消不启动服务 |
| T11 | 多子 View 定向通信与多目标业务协调 | 不编写订阅或反订阅即可完成通信；宿主明确目标；子功能不依赖父级或兄弟实现；交付审查确认未引入订阅 API 或观察图 |
| T12 | 同实例重复挂载、卸载、替换和重挂载 | 状态按所有权保留；稳定挂载不重复连接；旧 View 和旧回调失效；Godot 不移除无关节点 |
| T13 | 一子实例拒绝整个组合关闭 | 所有实例仍可用；其他 IO 未提前取消；服务资源未提前释放 |
| T14 | 关闭确认期间状态或成员变化 | 旧确认不能直接提交关闭；新成员和新业务条件纳入重新验证 |
| T15 | 子实例独立关闭及父级后续关闭 | 活动成员和地址正确移除；旧目标拒绝新消息；仍在释放的子资源继续被父级或宿主跟踪 |
| T16 | 导航目标关闭请求发起者 | 导航响应能够返回；不存在等待发起者退出的环；资源在发起者真实退出后才释放 |
| T17 | 不合作 IO、释放超时、取消等待和释放故障 | 逻辑关闭有效；资源不会被强制释放；超时不报告 Released；最终退出后释放；真实释放失败可观察 |
| T18 | 直接构造、标准 DI 多次创建和创建失败 | 实例与 Scope 正确隔离；共享服务按应用生命周期使用；外部传入服务不重复释放；失败无资源遗留 |
| T19 | 合法、非法及局部变更的用户声明 | 生成入口能被独立消费者调用；非法签名、歧义和冲突定位原声明；无关变更不触发全量无关生成 |
| T20 | 高频 HUD、大页面和慢 IO 的真实 UI | 有关字段更新、线程正确；默认展示合并有效；业务输入、定向消息、导航和提示不因合并而丢失 |
| T21 | 核心、单平台和双平台 NuGet 消费 | 不使用框架源码项目引用即可构建运行；核心无需 GUI；平台入口资产完整；双平台无重复生成 |

### 性能验收

| 维度 | 固定负载应覆盖 | 报告内容 |
| --- | --- | --- |
| 交互响应 | 两平台真实输入、慢 IO、更新风暴、大页面与高频 HUD | 中位和尾延迟、UI 工作量、有关字段刷新与展示合并效果 |
| 多实例与资源 | 创建、挂载、多开、路由、关闭和释放，逐级增加子实例数量 | 每实例内存、创建与释放成本、残留资源、平台连接与路由规模 |
| 派发与分配 | 纯转换、异步反馈、定向请求和 Post，等价并发策略 | 吞吐、延迟、框架分配、业务 State 分配、满载时行为 |
| 编译与生成 | 冷构建、增量变更、独立消费者与双平台资产 | 构建耗时、生成成本、重复资产、无关变更的影响 |

同环境、相同状态表示、等价语义比较最小手写实现、归档 v1 和 v2；创建与依赖注入增加标准 DI 对照。记录硬件、运行时、构建配置、负载、样本与统计方法，不用历史测量冒充当前结果。

稳定可复现的泄漏、错误写回、丢失业务事件和取消误判直接判失败。计时回归通过重复测量判断。数值预算尚未在设计阶段指定，由基线阶段的固定负载测量建立并记录；预算建立前只报告数据，不宣称高性能目标已经达成。跨 Feature 观察者订阅数量为零，不以增加逐字段框架订阅换取局部展示便利。

### 实施次序与完成条件

1. 建立核心公开行为与输入、验证、快照、操作身份、结果和并发契约，先证明纯转换、慢 IO 与 Latest。
2. 完成增量生成、标准 DI 工厂和用户声明消费，使三部分业务写法可实际编译运行。
3. 完成动态组合、定向路由、有界接纳、请求取消和整组关闭，验证等待环及资源释放边界。
4. 完成两平台真实绑定与生命周期，运行表单、工作区、多开编辑器和高频 HUD 场景。
5. 完成三包消费、四类性能证明和统一发布流程，清理已被替代的 v1 协议并同步文档。

完成要求是全部适用行为验收通过，真实平台和独立包消费者可用，四类成本有可复现数据与预算结论，v1 归档可恢复，v2 只保留一套默认协议。构建成功、基准烟测成功或图文校验成功均不能单独代替这些条件。满足后停止，不扩展到无具体业务需求的抽象或优化。

## Out of Scope

- v1 API 的源码或二进制兼容层、两套默认运行对象图，以及自动迁移全部外部使用者。
- 跨 Feature 的观察者发布订阅、主题总线、订阅者队列或共享可变业务状态树。
- 跨实例原子提交、分布式事务、取消已发生 IO 的自动回滚、强制终止任意外部任务。
- 自建通用 DI 容器、事件溯源与持久化回放、远程消息系统，以及 Avalonia 和 Godot 之外的新平台。
- 没有测量依据的池化、缓存和零分配承诺；重新创建已有归档或重复修改已完成的默认分支设置。
